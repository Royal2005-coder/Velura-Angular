# v0.3 — decisions that outlive their code

Status: **accepted 2026-09-04**. Three forks were reviewed and decided; the rejected options are kept below for the record.

## Problem

`ctx for` retrieves through `git blame`, so it only sees lines that exist in
HEAD. A decision attached to a deleted file, or to lines later removed from a
surviving file, is recorded — the gate already forces a `Decision:` onto any
deletion under a gated path — but unretrievable. The record exists; the index
does not reach it.

The moment this matters most is *resurrection*: an agent re-creating a file, or
re-adding a block, that was deliberately removed. That is precisely when the
tool is silent today.

## What the spike established

Run against a scratch copy of `ai-lab/sample` (2026-09-04):

1. **Tombstone lookup is one call.**
   `git log -1 -M --diff-filter=DR --name-status --format=%H%x1f%aI -- <path>`
   returns the deleting commit, its date, and a `D <path>` status line.
2. **Rename detection needs a second call.** With a single-path pathspec git
   cannot see the destination, so a `git mv` reports as `D`, not `R`. To learn
   the new name: `git show -M --name-status --format= <sha>` on the tombstone
   commit and look for `R<n>\t<old>\t<new>`. Only paid on the removed-path branch.
3. **History of a deleted path is queryable.**
   `git log --follow -i --grep=Decision: --format=%H -- <deleted path>` returns
   every decision-bearing commit in the file's life, deletion included. A path
   that never existed returns nothing — so the typo case stays an error.
4. **The orphan set is a set difference, and it works** — with one semantic
   surprise, covered under *Limitations*.
5. **`--line-porcelain` carries the final line number** (third header field),
   so a single whole-file blame can serve a `:a-b` range by filtering in
   process instead of a second `-L` invocation.

## Vocabulary

| section | meaning | how it got there |
|---|---|---|
| `active` | owns ≥1 surviving line in scope, not superseded | unchanged |
| `superseded` | explicitly retired via a reviewed `Supersedes:` commit | unchanged |
| `orphaned` *(new)* | carries a `Decision:`, touched this path, owns **no** surviving line, and was never superseded | its lines were removed or rewritten, or it only ever removed lines |
| `removed` *(new)* | the path itself is not in HEAD; this is the deleting commit | the tombstone |

The distinction an agent must be told: **superseded means someone decided the
decision no longer holds; orphaned means nobody decided anything — the code
went away.** A superseded decision's `rejected` list is no longer binding. An
orphaned decision's might be, and the fact that it lost its code without
anyone retiring it is the warning.

## Retrieval

### Existing path (the hot path — every hook invocation)

```
owners   = blame(path)                              # already computed
touched  = git log --follow -i --grep=Decision: --format=%H -- path
orphans  = touched − owners − {commits with a superseded-by note}
```

One additional `git log`, pathspec-limited and pre-filtered by `--grep`, so it
returns only decision-bearing commits — typically a handful. Each orphan then
costs the same record load as an active commit (trailers + three note refs),
through the existing bounded worker pool.

Superseded orphans are folded into `superseded`, not shown twice: an explicit
retirement outranks an implicit one.

### Removed path (replaces today's error branch)

```
if path not in HEAD:
    tomb = git log -1 -M --diff-filter=DR --name-status ... -- path
    if none:            → error as today ("no such path", never existed)
    renamed_to = git show -M --name-status <tomb.sha>  (R line, if any)
    orphans    = touched (all of them — nothing survives)
    removed    = record(tomb.sha) + at + renamed_to
```

Zero cost on the hot path: only runs when blame has already failed.

### Range scope

**Decided: one whole-file blame, filter by final line in Go.** One process
instead of two, and `orphaned` is well-defined for ranged queries because it is
a file-level property — a commit either owns surviving lines somewhere in the
file or it does not. Cost to watch: on a very large file with deep history,
`-L` lets git skip work a whole-file blame does not. The bench repo gets a
10k-line case and the numbers go in the release notes.

*Rejected:* keep `-L` and compute `orphaned` only for whole-file scope. Faster
on huge files, but a ranged query would silently lack a section the whole-file
query has — a trap for anyone scripting it.

### Noise control

**Decided: threshold on by default.** A churned file has a long tail of orphaned decisions and dumping them all makes
the report worse than no report. Default threshold — show an orphan only if:

- `Reversible` is `never` or `restore-only`, **or**
- it has an open incident attributed to it.

Everything else is counted, not printed: `orphaned_hidden: 7`, so the agent
knows there is more and `ctx for -all` shows it. A `Reversible: true` decision
whose code is gone is, by its own declaration, cheap history.

*Rejected:* show every orphan (a long tail agents learn to skip), and show
none unless asked (the resurrection warning — the highest-value case — would
only fire if someone remembered to ask).

Key order: `scope`, `warnings`, `removed`, `active`, `superseded`, `orphaned`,
`open_incidents`, `orphaned_hidden`, `error`.

`orphaned` is always present (like `active`/`superseded`) so consumers can rely
on the key; `removed` and `orphaned_hidden` appear only when non-zero. This
changes every golden file by one line; re-baseline once as part of the release.

JSON: `removed` (object, omitempty), `orphaned` (array, never null),
`orphaned_hidden` (int, omitempty). Full SHAs as today.

## Hook

Two changes to `~/.claude/hooks/ctx-context.sh`:

1. **Resurrection.** A `Write` to a path whose directory does not exist bails
   today (`[ -d "$dir" ] || exit 0`). Walk up to the nearest existing ancestor
   to find the repository root, then let `ctx for` run — the removed-path
   branch is what fires.
2. **Emptiness by structure, not string match.** Call `-format json` once and
   test with `jq` (`(.active|length)+(.superseded|length)+(.orphaned|length) == 0
   and .removed == null`). Render YAML only on a hit. Miss path stays one call.

## What does not change

- **No new persistent state.** Everything is computed at query time from the
  commit graph. `reindex` is untouched, and the philosophy holds: notes remain
  the only derived state, and nothing new has to be rebuilt or backed up.
- **No new gate rule.** Deleting under a gated path already demands a
  `Decision:`. Making `Reversible:` mandatory on deletions was considered and
  rejected for 0.3: ceremony creep before the feature has proven its signal.
- **Directory scope** (`ctx for infra/storage/` listing everything removed
  beneath a prefix) is **deferred to 0.4**. It is the expensive shape — a
  history walk with pathspec, seconds on a monorepo — and it should wait until
  the orphaned section has shown whether it is signal or noise on a real repo.

## Limitations — stated up front

**Granularity is the commit, not the line.** A commit that changed
`storageClassName` *and* added the pin annotation stays `active` as long as
the storageClassName line survives, even after the annotation lines are
deleted. The pin decision is not flagged orphaned because its commit still
owns code. The spike hit exactly this case. No tooling fix in 0.3; the
mitigation is the shape the gate already encourages — one decision per commit.
Worth a line in `docs/agents.md` and in the skill.

**Pure-removal commits always appear orphaned.** A commit that only deletes
lines never owns any, so its `Decision:` ("drop the unused annotations") lands
in `orphaned` by construction. This is arguably correct — it *is* a line-level
tombstone, and the reason lines vanished is useful — but it is a different
kind of entry from "a past decision whose code got replaced".
**Decided: one section, no tag.** The decision text usually makes the
distinction self-evident, and it is one fewer key per entry. *Rejected:* a
`kind: removal` tag via `--numstat` on the same log call — free to compute, but
paid for on every entry in tokens.

**You still cannot warn about what nobody named.** Deletion does not make an
unwritten constraint retrievable.

## Tests

- `gitx`: tombstone parse for `D` and for `R<n>` (rename → `RenamedTo`);
  never-existed path → empty; `--follow` history on a deleted path.
- `ctxcmd`: orphan set = touched − owners − superseded; threshold hides
  `Reversible: true` with no incident and shows `never`/`restore-only`/open
  incident; `orphaned_hidden` count; removed-path report; typo path still an
  error; a superseded commit that also lost its lines appears once, under
  `superseded`; range scope via in-process filter yields the same `active`
  set as v0.2 `-L` on the golden scopes.
- `render`: new sections and key order; `orphaned: []` always present;
  `removed` omitted when absent; JSON never-null arrays.
- `cmd`: `-all` flag; exit code unchanged.
- Hook: pipe-test a `Write` to a deleted path and to a path in a
  not-yet-existing directory.
- Bench: extend the 150-commit repo with a deletion-heavy file and a 10k-line
  file; record whole-file vs `-L` blame timings so the range-scope decision
  ships with numbers, not a guess.

## Measurement gate — run 2026-09-04, inconclusive

Ran against `ai-lab/infra/ai-lab-v2` (388 commits, 729 files, the live ArgoCD
source). **The gate could not be satisfied, for a structural reason rather than
a bad result:** that repo carries zero `Decision:` trailers in its entire
history, so `orphaned` is empty in all 60 files swept and `orphaned_hidden` is
0 everywhere. There is nothing yet for the threshold or the cap to be right or
wrong about.

What the run did establish:

- **Performance on real data:** 101ms per file, 9.3 lines and 1.6 entries per
  report on average. Cheap enough for the pre-edit hook.
- **The shallow-clone warning fires correctly in the field.** That checkout was
  cloned at depth 1, and 32% of blamed lines across 40 files collapsed onto the
  single graft commit — every one of them misattributed, for `ctx` and for any
  human running `git blame`. Fixed with `git fetch --unshallow`; the check is
  now step one of `docs/adoption.md`.
- **Two real defects, both found by using the tool rather than testing it:** a
  rename bundled with edits fell below git's default similarity threshold so
  `renamed_to` came back empty, and `init` configured push refspecs on every
  remote including one pointing at an unrelated project.

The repo is now initialised with a single gated path
(`infra/terraform/live/vault`) and the `commit-msg` hook installed, so the gate
can be satisfied by ordinary work rather than by a constructed test.

**Tagging decision.** v0.3.0 is tagged on code completeness, which is the same
bar v0.2.0 was tagged on. Deferring the tag until field adoption would hold
this release to a standard the previous one did not meet, and would leave the
work unmarked for however long adoption takes. The tag does not claim the idea
is validated in the field — that remains open, and the threshold and cap are
still backed only by the synthetic 120-generation case above.

## Amendments from implementation (2026-09-04)

Three things the build found that the design did not:

1. **A cap was required, not just a threshold.** The cost threshold does not
   bound the section: a file rewritten repeatedly, each generation declaring
   `Reversible: never`, yields one qualifying orphan per generation. Measured
   at 120 generations: a 485-line, 14.6 KB report — produced in 0.15s and
   unreadable. `maxOrphansShown = 10` (newest first) brings that to 50 lines
   and 1.4 KB with `orphaned_hidden: 109`. `-all` lifts it.
2. **The tombstone was reported twice** — once as the `removed:` headline and
   again inside `orphaned`. It is now excluded from the orphan list.
3. **Blame cost, measured.** On a deliberately hostile file (10k lines, 201
   commits): whole-file blame 0.52s vs `-L` 0.38s, so the range decision costs
   ~0.14s at that scale and nothing at normal scale. The added history query
   (`log --follow --grep`) is unmeasurable at 0.00s. End-to-end `ctx for` on a
   10-line range of that file: 0.56s, dominated by blame.

The measurement gate above was run; see its outcome. Tagged v0.3.0.
